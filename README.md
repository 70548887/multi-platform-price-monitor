# 多平台商品价格监控

为内部团队维护平台、采集账号与规则，按小时采集全站商品，查看精确价格、走势、销售状态与站内告警。平台按亿乐、易客分类型，分别提供 `xiaohong66.com` 与 `fans8.top` PC 版采集适配器，不同平台与账号的数据分别保存。

后端为 Python / FastAPI / Celery，数据库为 PostgreSQL，Redis 用于任务队列、锁与共享限速。前端为 Vue 3 / TypeScript / ECharts。API、采集 Worker、独立 AI Worker 与调度器各自运行。

## Docker 部署

需要 Docker Engine、Docker Compose v2 和首次生成密钥用的 Python 3。部署环境使用 Linux 容器。

```powershell
python scripts/init_env.py
docker compose up -d --build --wait --wait-timeout 240
docker compose ps
```

也可执行 `./scripts/start.ps1`；Linux 执行 `bash scripts/start.sh`。密钥初始化只运行一次，已有 `.env` 会拒绝覆盖。首次安装默认创建管理员 `admin / admin888` 和普通成员 `user / user123`；普通成员初始没有平台数据权限，由管理员分配。可通过 `ADMIN_USERNAME`、`ADMIN_PASSWORD`、`DEFAULT_USER_USERNAME`、`DEFAULT_USER_PASSWORD` 环境变量覆盖初始化账号。数据库已有用户时，重启或升级不会创建默认账号，也不会重置密码。

默认访问 `http://127.0.0.1:28671`。若需局域网访问，在 `.env` 配置 `WEB_BIND` 和 `WEB_PORT`。HTTPS 反向代理部署时将 `COOKIE_SECURE=true`。数据库和 Redis 未向宿主机开放端口。PostgreSQL 与 Redis 数据位于 Compose 持久卷。

```powershell
docker compose logs --tail 100 api worker ai-worker beat
docker compose stop
docker compose up -d
```

`stop` 保留数据。删除持久卷会丢失数据库与队列数据，应先完成备份。调度器只运行一个实例；Worker 可扩容，平台锁和共享限速仍以平台为单位生效。

## 接入平台

1. 登录后台，新增平台，选择平台类型及对应采集版本，设置唯一账号标识。Fans8 归入易客系列；易客标准版本暂存配置，待提供站点资料验证后启用采集。
2. 按页面提示导入该平台账号的会话信息并执行会话检查。会话加密保存；失效后暂停采集，重新连接后恢复。
3. 配置采集周期、分类、分页与字段规则，运行测试预览，确认样本单价、展示数量和单位后发布规则。
4. 手动运行首个采集批次，在任务页面确认完整性，再开启周期采集。

已有会话、已发布规则或商品历史的连接会锁定类型与版本，新版本应新增连接。未使用的连接可以更换版本，并生成对应版本的新草稿。类型与版本、规则校验和 Worker 分派保持绑定，待验证版本会在连接、测试、发布、手动采集和调度入口被拦截。

管理员可在本机执行 `python scripts/connect_platform.py --platform-id 对应平台编号`，在新开的 Chrome/Edge 窗口手动登录主账号。工具根据版本进入登录页并加密保存会话，无需把密码发送到聊天中。Fans8 使用自身的 Bearer 会话与 GET 商品接口；`Bs` 表示下单倍数，不用于乘算价格。源站未明确计价单位时会标记待核对。

Fans8 的目录会在采集中新增或删除商品。已实测 `PageCount=5000` 可一次返回约 4900 个商品，默认规则因此使用单页 5000 条、60 秒超时，减少跨页变动；超过单页容量时仍严格校验每页总数和唯一编号。发生变化或缺页时保留不完整批次，不把未采商品判为下架。游客登录已实测可读商品，游客身份 `Id=0`；使用游客时应新增独立连接和账号标识，保留与主账号的价格上下文。

商品编号关联历史，更名不会产生新商品。价格使用精确小数，API 以字符串返回；基础单价和展示数量分别保存。停售、缺失、异常单位有独立状态，停售零价不会按正常降价处理。未采到的商品不会因不完整批次被批量判为下架。

全网比价由管理员按类目建立统一商品，再关联多个平台的同类或相似商品。相似模式保留各平台的原始报价与计价说明；同规格模式只有满足币种、单位、质量、有效期和采样时差条件的跨平台报价才标出最低价。首次采集建立基线，之后记录价格与销售状态变化。旧批次不会覆盖较新的当前价格。

### 成员前台与管理后台

成员登录入口为 `/login`，前台 `/`、`/products`、`/events`、`/compare` 用于查看价格与比价。管理入口为 `/admin/login`、`/admin`；平台、采集、成员、代理和升级分别位于 `/admin/platforms`、`/admin/runs`、`/admin/users`、`/admin/settings/network`、`/admin/settings/update`。旧管理路径会跳转到新的后台路径，普通成员仍会被权限守卫拒绝。

管理员在“成员管理 → 编辑 → 可查看的平台”分配平台。管理员默认查看全部；普通成员（包括升级前已有成员）默认不获得任何平台权限，需明确勾选。全选仅授予当时已有的平台，后续新增平台需要再次分配。保存后下一次 API 请求立即使用新的权限；商品列表、详情、历史、事件、统计、类目和映射子商品均由后端过滤，不能通过修改 URL 越权。将管理员降为查看者时，未提供平台列表则清空授权。

### 源类目与全网比价

商品中心可按交易平台和源类目筛选。亿乐保留源站返回的类目名称；Fans8 保留 `ClassName1 / ClassName2 / ClassName3` 分类路径。源站没有提供类目时显示未分类，不根据商品标题推测类目或编造编号。

在 `/admin/compare` 先建立一级类目（例如“抖音、快手、小红书、哔哩哔哩”），再在类目下建立“视频、直播”等二级类目，之后在“抖音 / 视频”内建立“抖音视频点赞”等统一商品并关联多个交易平台报价。支持继续建立子类目，最多 8 层。同一个父类目下名称不能重复，但“抖音 / 视频”和“快手 / 视频”可以同时存在。选择父类目会展示整个分支的商品，商品选择器与详情页显示完整类目路径。

每个统一商品最多关联 5000 条报价；选择器可按平台、源类目、关键词和页码寻找商品，跨页选择会保留，也允许先建立空商品再补关联。源商品已有归属时不会被静默移动。比价类目独立于源站原类目；移动类目不会改变商品或价格历史，禁止将类目移入自身或其后代。删除含有子类目或统一商品的类目前必须先移走内容。普通成员仅能看到有权商品所在的分支及必要祖先，所有数量按其权限计算。

关联商品时可切换“智能关键词推荐”，或点击“用商品名称推荐”。例如 `B站 点赞` 会识别哔哩哔哩、bili、BL、赞等已知别名，按名称与源类目命中程度排序；默认同时满足全部关键词，可显式切换任一关键词的宽松模式，并输入 `评论 分享 三连` 等排除词。抖音与 TikTok 不视作同一业务，短英文缩写有边界校验，避免 BL 误命中 blue。每项会显示名称/类目匹配原因以及评论点赞、组合套餐、单位待核验等提醒；关键词推荐不保证规格或用途相同，仍需人工核对。

支持选中本页可关联项，或批量读取全部匹配结果加入本地草稿（最多前 5000 条）。已有其他统一商品归属的候选会跳过；分页数量变化、缺页、重复、失败或取消时不会提交半批选择。关键词或筛选变化会使旧请求失效，已有选择跨页保留。只有点击“保存商品”后才真正建立关联，不会随推荐自动绑定或采集新商品。

智能推荐的各页包含同一份候选元数据的版本标识；即使商品总数未变化，名称、报价、源类目、归属或最后采样时间变化也会使批量选择中止，要求重新搜索核对。校验失败响应仅返回字段位置和错误说明，不回显密码、会话或带认证信息的网址原文。权限收回后，商品详情刷新会清除旧的报价与历史数据。

推荐接口的数量、版本标识和分页商品使用同一只读数据库快照；汇总走势的当前极值与历史观测也使用同一请求快照，避免采集恰好写入时同一响应出现前后口径不一致。跨请求仍会读取最新数据，候选版本变化时需重新核对。刷新报价成功后会同步刷新汇总走势。

后台一级菜单“比价类目管理”（`/admin/comparison-categories`）提供独立的分类维护页，可新增一级/子类目、编辑名称与说明、修改排序值和移动上级分类。排序值越小越靠前，同值按创建顺序排列。原全网比价页面和其中的类目入口继续保留，两处使用同一份分类数据；成员没有此管理入口或修改权限。

统一商品详情新增汇总价格走势，按当前关联且已授权的商品回看最近 1、7、30 天的历史。每小时每件商品采用最后一次观测，分别统计最低和最高有效基础报价，缺失时段留空；币种、源单位和展示数量不同的报价分组查看，不混算。当前最低/最高参考价仅统计新鲜、在售且价格有效的报价。同类或单位待核验的价格仅供参考，不等同于同规格全网最低价。关联关系调整后，走势按当前关联范围重新查询，不能当作历史成员关系审计。列表可按基础单价或展示价格升降序排列，价格使用精确小数字符串比较，不同币种分别排序。

### AI 数据检查与自动整理

管理员在“系统设置 → AI 数据验证”配置公开 HTTPS Base URL、模型和加密保存的 API Key。默认关闭每日任务与自动应用；填写并保存后可启用。AI 数据中心 `/admin/ai-analysis` 提供运行概览、待审核建议、分析报告和处理记录。所有报告与操作仅管理员可见。

配置页的“检查已保存连接并读取模型”只请求保存地址的 `GET /models`，不发送商品、推理任务或新的密钥，也不扣本系统分析额度。修改配置后先保存再检查；模型列表会筛选、去重并限制数量，选择模型后仍需保存。鉴权与模型列表可用不代表推理额度可用。接口不支持模型列表、限流、超时或配置在检查期间变更时显示相应提示；不会自动退回其他线路或重复请求。

运行概览会显示最近任务失败原因和下一步操作，失败报告也提供对应说明。HTTP 429 需要核对服务商额度或并发限制；本系统每日额度耗尽和服务端限流分开展示，均不自动重复调用。历史报告中的旧摘要仍保留，以批次错误及当前诊断提示核对原因。

每日北京时间09:00由应用Beat创建任务，分析前一北京时间自然日；手动分析最近24小时。默认每日最多1000件、20次请求（失败请求同样计数），手动与定时任务共享额度，每批最多50件。70%名额优先新增、变动或异常商品，30%按最近成功检查时间轮巡，不足互补，各交易平台轮流取数。同日普通任务跳过已经发送的商品；失败仅手动重试，已在其他任务成功检查的商品不重复重试。

程序核对覆盖全量数据库统计；AI只检查实际发送的样本，不表示全站或源站价格已验证。报告分别标记统计窗口、期内观测与当前商品状态生成时间，展示批次期望、已见、实际入库数量。`程序核对`无需Key、不调用模型。模型返回Token用量时据实记录，否则显示未知，不估算费用。

AI分析运行在独立`ai`队列/`ai-worker`进程，采集Worker只消费`celery`队列。任务发送前持久化请求额度及批次状态，重复投递不会重发；进程中断的在途请求标为结果未知，不自动重扣费。停止操作只取消后续批次，已发出的请求仍可返回报告。旧报告继续可读，首次上线不自动处理历史建议。

启用自动应用后，只处理未关联、有效且新鲜的商品。业务平台、服务动作、视频/直播场景须经本地别名规则确定且一致，目标必须使用已有类目和唯一的同类/相似统一商品。自动新建统一商品至少需要两个交易平台，不能自动建立新类目；同规格、含糊或冲突建议进入人工审核。现有人工关联、源类目、价格和历史观测不被模型修改。

管理员可修改建议目标、采纳、拒绝，并查看应用前后证据。应用使用增量关联和事务锁；撤销核对商品及统一商品版本，后续人工修改造成冲突时拒绝覆盖。拒绝或撤销的同内容建议不会再次自动应用。首次真实模型调用须配置服务商Key后进行；模拟模型测试通过不等同于已验收真实接口。

### 成员提交平台收录

前台“提交平台收录”（`/platform-submissions`）可提交公开平台名称、HTTP/HTTPS 网址及说明，成员只查看自己的申请。网址只保存公开 origin，不保存路径、查询或片段；不要提交密码、Token 或代理凭据。每人最多 5 条待审核申请，同一网址的待审申请不能重复提交。提交过程不会访问源站，也不会自动建立平台或启动采集。

管理员在“平台收录审核”（`/admin/platform-submissions`）查看全部申请，并填写采纳或暂不收录的反馈。采纳仅代表审核通过，管理员仍需在平台管理中核对适配版本、授权账号、采集规则及平台可见范围。未获平台权限的成员也可提交收录建议，但提交或获采纳不会扩大其数据查看权限。

点击商品进入 `/compare/{id}` 或后台 `/admin/compare/{id}`，可查看所有已授权平台的报价、源类目、基础单价、展示数量、在售状态和采样时间，并进入原商品走势。“同类/相似”模式可汇集不同单位或币种的报价，不自动判定最低价；“同规格”模式保留严格校验，但停售、陈旧或不符合比较口径的关联报价仍会完整显示，并说明原因。成员的平台权限同时限制类目计数、商品目录和详情中的报价。旧 `/mappings` 与 `/admin/mappings` 页面跳转到全网比价，既有 API 和关联记录继续兼容。

旧 Fans8 商品若类别为空，可从已保存的最新原始观测恢复，无需重新采集。先运行 `python scripts/repair_product_categories.py` 预览，确认后用 `python scripts/repair_product_categories.py --apply` 应用。工具等待规划锁、拒绝活动 Fans8 批次，先将旧类别备份至 `.runtime/category-repair/`，仅修改当前商品的空类别，不修改价格、观测记录或采集结果。

## 本机 Windows 开发

项目提供 `scripts/native.ps1` 管理独立的本项目进程，不安装系统服务。默认使用已安装的 PostgreSQL16 二进制、现有 Redis 可执行文件，独立数据目录为 `.runtime`，端口为 PostgreSQL `55432`、Redis `56379`、API `28671`、前端 `28672`。可通过脚本参数指定二进制路径。

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements-dev.txt
Push-Location frontend
npm.cmd ci
Pop-Location
./scripts/native.ps1 -Action services
./scripts/native.ps1 -Action start
./scripts/native.ps1 -Action status
```

本机模式会生成包含独立数据库连接的 `.env`，不会覆盖已有文件；若已有 Docker 配置，需要自行填写本机 `DATABASE_URL` 与 `REDIS_URL`。数据库初始化在独立目录进行，保留现有系统服务。

访问 `http://127.0.0.1:28671` 使用已构建网站，或访问 `http://127.0.0.1:28672` 使用前端开发预览，开发代理连接 API。两种部署方式使用相同默认网站端口，原生模式与 Docker 模式请择一启动。日志在 `.runtime/logs`。代码更新后执行 `./scripts/native.ps1 -Action restart-app` 重启 API、采集 Worker、AI Worker、调度器与前端，保留数据库、Redis 和其他独立辅助进程。停止时执行 `./scripts/native.ps1 -Action stop`，只停止记录的且路径与创建时间匹配的本项目进程，保留所有数据。Windows Celery 使用 `solo` 模式做开发验证；部署使用 Compose 的 Linux Worker。

## 验收与持续观察

先完成一个真实平台的成功采集，再开始持续观察。以下命令从 `.env` 读取后台登录账号，通过登录 Cookie 查询健康与运维统计，不修改商品或触发采集：

```powershell
python scripts/acceptance_watch.py --once
python scripts/acceptance_watch.py --duration-hours 48 --interval-seconds 300
```

本机开发使用 `--url http://127.0.0.1:28671`。可通过 `--env-file` 或 `MONITOR_ADMIN_PASSWORD` 环境变量传入登录密码，避免将密码写在命令行。

观察数据写入 `var/acceptance/*.jsonl`，包含真实 UTC 时间、健康状态、各批次计数、平台最近成功时间及最终结果。每次运行使用独立文件，不能把多次中断观察拼成连续 48 小时。`--once` 只生成一次样本，永远不会认定 48 小时通过。Ctrl+C 会记录 `interrupted`，请求或采集异常会进入失败结果。

`backend/requirements.txt` 固定已验证的应用主依赖，Docker 从此文件安装；测试依赖单独列在 `backend/requirements-dev.txt`。这些文件没有冻结工作站上的其他工具包。

通过标准包含：实际覆盖 48 小时、健康采样无失败、每个启用平台按周期产生成功批次、无新增失败或不完整批次、无过期会话或陈旧成功时间。观察脚本只验证服务侧证据；采集价格与登录页面样本的一致性仍需按真实平台核验。

记录结束后还需执行独立逐批复核，不能只凭观察器的汇总标志宣布通过：

```powershell
python scripts/verify_acceptance.py var/acceptance/对应记录文件.jsonl
```

## 采集代理与系统设置

管理员在“系统设置”配置隧道代理和境外代理，在“平台管理”逐个平台选择直连、隧道或境外线路。既有连接默认直连；隧道代理预留为停用状态。代理地址支持 HTTP/HTTPS 与账号密码认证，加密保存在数据库，页面与接口只返回“已配置/未配置”和启停状态。

代理地址留空表示保留已保存的地址，“清除”会删除凭据并停用该代理。使用已停用或尚未配置代理的平台会明确报错，不自动回退直连。路由同时用于会话检查、规则预览和周期采集；每个批次启动时读取一次配置。代理连接故障与源站 HTTP 502 等错误会在任务记录中分别说明。

代理只改变服务器采集出口，无法保证源站不会超时或返回错误。独立登录窗口使用操作者本机网络；选用代理的平台，其候选会话交由服务器按所选线路校验，无需向登录助手下发代理凭据。本机无法打开源站时，可在能访问的浏览器完成登录后通过后台导入会话。代理密码、Token 和真实地址不写入仓库、版本包或审计消息。

## 在线升级

系统更新页面只允许管理员操作。更新来源是当前 GitHub 仓库的正式 Release，发布资产必须包含 `price-monitor-{version}.tar.gz` 和同名 `.sha256` 校验文件。服务只负责检测、下载、校验和创建更新任务，真正替换代码与重启由宿主机更新器完成。

非敏感配置位于 `config/update.yaml`。默认 `proxy_route: "overseas"` 复用“系统设置”里加密保存且已启用的境外代理，GitHub 版本检测、SHA256 校验文件、正式发布包和允许域名间的下载重定向均使用该线路。代理凭据只在请求时解密到内存，不写入更新任务、历史、审计或前端。代理未配置、被停用、无法解密或连接失败会明确报错，不自动退回直连。

需要独立更新出口时改为 `proxy_route: "custom"`，通过 `UPDATE_PROXY` 环境变量设置；`proxy_route: "direct"` 明确使用直连。旧配置没有 `proxy_route` 时保持原 `UPDATE_PROXY` 行为。选择 `overseas` 后，`UPDATE_PROXY` 不覆盖管理员选择的境外代理线路。GitHub Token 继续通过环境变量提供：

```powershell
$env:UPDATE_GITHUB_TOKEN = '从密码管理器读取的 Token'
$env:UPDATE_PROXY = '可选的本机代理地址'
```

修改“系统设置”中的境外代理后，下一次检测或下载即使用新配置，更新页面仅显示配置与启用状态。宿主机更新器使用后台已下载、校验并签名入队的本地发布包，不会再次访问 GitHub；本机健康检查、数据库和 Redis 保持本地连接。安装依赖、容器镜像拉取涉及 pip/npm 或 Docker 服务自己的网络设置，不会把代理密码注入应用子进程或 Docker Socket。

Windows 本机模式运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/update_host.ps1 -Mode native
```

Linux/Docker 部署运行：

```bash
bash scripts/update_host.sh --mode compose
```

宝塔面板使用 Docker 管理器时，按 Linux/Docker 模式运行 updater。API 容器用户和 updater 用户必须一致，并且该用户需要执行 Docker Compose 的权限：

```bash
export APP_UID=$(id -u www)
export APP_GID=$(id -g www)
mkdir -p data/update data/backups
chown -R "$APP_UID:$APP_GID" data/update data/backups
usermod -aG docker www
```

如果使用宝塔 Supervisor，可将 updater 配置为常驻进程：

```ini
[program:price-monitor-updater]
command=/bin/bash /www/wwwroot/price-monitor/scripts/update_host.sh
directory=/www/wwwroot/price-monitor
user=www
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
```

当前宿主机 updater 的 `native` 模式用于 Windows 本机进程；Linux 宝塔的自动应用链路使用 Docker Compose。宝塔直接托管 Uvicorn、Celery 和 Nginx 的非 Docker 组合需要把停止和启动命令接入宿主机服务管理器后再启用自动应用。

Docker 部署需让 API 容器用户与宿主机更新器用户使用相同的 `APP_UID`、`APP_GID`，并提前创建可写目录：

```bash
mkdir -p data/update data/backups
chown -R "$APP_UID:$APP_GID" data/update data/backups
```

更新器只替换 Release 清单中的受管文件，保留 `.env`、数据库、Redis、平台会话、历史价格、运行目录和备份。更新失败会恢复最近备份；Docker 更新不挂载 Docker Socket。

Docker 部署可执行：

```powershell
python scripts/backup.py
```

当前本机模式使用 `python scripts/backup.py --mode native`。该模式从 `.env` 读取项目数据库连接，只向本机 PostgreSQL 执行 `pg_dump`；完成后用 `pg_restore --list` 检查备份目录，不恢复或修改原数据库。2026-10-25 已使用真实数据生成并验证一次备份。

备份以 PostgreSQL 自定义格式写入 `backups`，成功完成后才发布最终文件并计算 SHA256。恢复前应另行验证备份可读性，并停止写入任务。该脚本不自动清除数据库或恢复覆盖数据。

请单独妥善备份 `.env`。数据库恢复后仍需要原 `ENCRYPTION_KEY` 解密平台会话；更换初始管理员环境密码不会直接修改已有数据库用户密码。日志、备份、会话、`.env` 和 `.runtime` 均排除在版本控制及容器构建上下文之外。
